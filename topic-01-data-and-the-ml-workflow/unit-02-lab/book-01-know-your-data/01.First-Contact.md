## Exercise 1.1: Shape, types, and a column that isn't there

**Step 1:** Get the basic profile:

```python
# section1_profile.py
print(df.shape)
print(df.dtypes.value_counts())
print(df.isna().sum().sum())        # total blanks in the whole file
```

You'll find **30,000 rows and 25 columns**, every column numeric, and, note this, **zero blanks**. Hold onto that; Section 4 will show it isn't the good news it looks like.

**Step 2:** Now read the column names carefully:

```python
print([c for c in df.columns if c.startswith("PAY_") and "AMT" not in c])
```

```
['PAY_0', 'PAY_2', 'PAY_3', 'PAY_4', 'PAY_5', 'PAY_6']
```

**Question:** These six columns are the repayment status for six consecutive months. Count them. The series runs `PAY_0, PAY_2, PAY_3, ... PAY_6`: there is no `PAY_1`. Is a month missing, or is `PAY_0` simply mis-named? Which explanation would you rather be wrong about, and how would you check? (This is a one-line quirk that has confused a great many people using this dataset. From Week 2 onward we rename `PAY_0` to `PAY_1`, because it is the most recent month and the naming is almost certainly an off-by-one in the original upload.)

## Exercise 1.2: Audit the data against its documentation

The dataset ships with a codebook. `SEX` is 1 = male, 2 = female. `EDUCATION` is 1 = graduate school, 2 = university, 3 = high school, 4 = others. `MARRIAGE` is 1 = married, 2 = single, 3 = others. The `PAY_` columns are −1 = paid duly, 1 = one month's delay, 2 = two months' delay, and so on up to 9.

That's what the documentation *says*. Now check it.

**Step 1:** List the codes that are actually present:

```python
# section1_audit.py
for c in ["SEX", "EDUCATION", "MARRIAGE"]:
    print(f"{c:10s} {sorted(df[c].unique().tolist())}")
print(f"{'PAY_0':10s} {sorted(df['PAY_0'].unique().tolist())}")
```

```
SEX        [1, 2]
EDUCATION  [0, 1, 2, 3, 4, 5, 6]
MARRIAGE   [0, 1, 2, 3]
PAY_0      [-2, -1, 0, 1, 2, 3, 4, 5, 6, 7, 8]
```

`SEX` behaves. The other three do not. `EDUCATION` has a 0, a 5 and a 6 that the codebook never mentions; `MARRIAGE` has a 0; and `PAY_0` has a **−2** and a **0**, neither of which is documented.

**Step 2:** Find out how much data this affects:

```python
print("EDUCATION in {0,5,6}:", df.EDUCATION.isin([0, 5, 6]).sum())
print("MARRIAGE == 0      :", (df.MARRIAGE == 0).sum())
print("PAY_0 in {-2, 0}   :", df.PAY_0.isin([-2, 0]).sum(),
      f"({100 * df.PAY_0.isin([-2, 0]).mean():.1f}%)")
```

```
EDUCATION in {0,5,6}: 345
MARRIAGE == 0      : 54
PAY_0 in {-2, 0}   : 17496 (58.3%)
```

**Question:** The `EDUCATION` and `MARRIAGE` problems are small: 345 and 54 rows. The `PAY_0` problem is not: **58.3% of the column is undocumented codes**. The single most important feature in this dataset is mostly values the codebook doesn't explain. What are your options, and which would you defend? Write your answer down before continuing, because you will act on it in Week 2.

**Step 3:** When documentation fails, the data can still talk. Ask what the undocumented codes *behave* like:

```python
rate = df.groupby("PAY_0")["default.payment.next.month"].agg(["mean", "size"])
print(rate.assign(mean=rate["mean"].round(3)).to_string())
```

```
        mean   size
PAY_0
-2     0.132   2759
-1     0.168   5686
 0     0.128  14737
 1     0.339   3688
 2     0.691   2667
 3     0.758    322
```

**Task:** The documented "paid duly" code (−1) defaults at 16.8%. The undocumented −2 and 0 default at 13.2% and 12.8%, *lower* than paying duly, and nothing like the 33.9% of a one-month delay. Write one sentence proposing what −2 and 0 most likely mean. Then write a second sentence saying how confident you are, and why an inference from behaviour is weaker evidence than a codebook would be.
