# Section 3: Correlation and its traps

## What You'll Learn

Correlation puts one number on "do these move together". You'll see that number be wrong in both directions on this dataset, and you'll learn why a heat map is a redundancy detector as much as a discovery tool.

## Exercise 3.1: Pearson against Spearman

**Step 1:** Compute both for three pairs of columns:

```python
# section3_correlation.py
for a, b in [("BILL_AMT1", "PAY_AMT1"),
             ("LIMIT_BAL", "BILL_AMT1"),
             ("LIMIT_BAL", "AGE")]:
    p = stats.pearsonr(df[a], df[b]).statistic
    s = stats.spearmanr(df[a], df[b]).statistic
    print(f"{a:10s} vs {b:10s}  Pearson={p:6.3f}   Spearman={s:6.3f}")
```

```
BILL_AMT1  vs PAY_AMT1    Pearson= 0.140   Spearman= 0.502
LIMIT_BAL  vs BILL_AMT1   Pearson= 0.285   Spearman= 0.054
LIMIT_BAL  vs AGE         Pearson= 0.145   Spearman= 0.186
```

**Question:** Look at the first two rows carefully, because they fail in *opposite* directions.

- For `BILL_AMT1` vs `PAY_AMT1`, Pearson says 0.14, which reads as "barely related". Spearman says 0.50. Bigger bills really do go with bigger payments; a handful of enormous values wrecked the straight-line view. **Pearson understated it.**
- For `LIMIT_BAL` vs `BILL_AMT1`, Pearson says 0.29 and Spearman says 0.05. Here the extreme values *manufactured* an association that the rank view says is essentially absent. **Pearson overstated it.**

Write one sentence on why "just use Pearson" is not a safe default, using these two rows as your evidence.
