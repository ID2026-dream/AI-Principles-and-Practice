# Submitting This Lab

You submit **your Sections 1 to 8 work, as one zip**, to a OneDrive folder.

A script in the lab folder builds the zip for you, so that every submission
arrives named the same way and with nothing missing. There is nothing to set
up and no account to create, and it works the same way every week.

## The three steps

### 1. Answer as you go

Download **Week 01 Submission Kit** from this unit and unzip it into your lab
folder, beside `UCI_Credit_Card.csv`. It holds three files:

| File | What it is |
|---|---|
| `SUBMISSION.md` | Your answers, one part per lab section |
| `make_submission.py` | Builds the zip |
| `setup_check.py` | Environment report |

Open `SUBMISSION.md` and fill in each section as you finish it. Most of the
questions are the checkpoint questions you have already talked through at the
bench, so this is a transcription job rather than extra work — as long as you
do it at the time.

Keep your code in the lab folder as you write it: `section1_profile.py`,
`section4_missing.py`, `exercise_8_3.py`, or one notebook if you prefer. It all
goes in automatically.

### 2. Build your submission

In the lab folder, with your virtual environment active:

```bash
python make_submission.py
```

It asks for your student number the first time and remembers it afterwards.

The script checks your work, runs `setup_check.py`, gathers your files, and
produces a single zip named after you:

```
submission-week01-20012345.zip
```

It tells you exactly where that file is when it finishes.

**If it stops instead**, read the message. It stops for one reason only: your
`SUBMISSION.md` still has `TODO` markers in it, which means it is not finished.
It prints the line number and the question for each one. Finish them and run it
again.

## What is in the file

You can open the zip and look — there are no surprises in it:

| Inside the zip | What it is |
|---|---|
| `SUBMISSION.md` | Your answers for Sections 1–8 |
| `section*.py`, `exercise*.py`, `*.ipynb` | Your code, picked up automatically |
| Any plots you saved | The figures you produced |
| `submission/` | Anything else you chose to include |
| `setup_check_output.txt` | Your environment report, captured automatically |
| `manifest.json` | Your student number, the week, and a timestamp |

The provided `UCI_Credit_Card.csv` and the `figures/` folder are deliberately
left out. We already have those, and they would make your upload 3 MB for no
reason. Everything else typically comes to well under 100 KB.

Nothing is sent anywhere by the script. It uses the standard library only, runs
entirely on your machine, and writes one file. The only thing that leaves your
computer is the zip you upload yourself.

## Common problems

**"It says my SUBMISSION.md is not finished."** There is still a `TODO` in it.
The script prints the line number and the question for each one. Answer that
section and delete the marker.

**"I need to submit even though it is incomplete."** You can, and sometimes
that is the right call:

```bash
python make_submission.py --force
```

It is recorded as incomplete, which is better than not being recorded at all.

**"I want to see what would go in before it builds."**

```bash
python make_submission.py --dry-run
```

**"My code is in a different folder."** Copy it into the lab folder, or into a
folder called `submission` inside it. The script only looks where it is.

**"It picked the wrong week."** Tell it:

```bash
python make_submission.py --week 1
```

**"I typed my student number wrong."** Delete the file `.student_number` in the
lab folder and run the script again.

**"The script will not run at all."** Do not let that stop you submitting. Zip
the lab folder yourself, leaving out `UCI_Credit_Card.csv` and `figures/`, name
it `submission-week01-<your student number>.zip`, and upload that. Then post
what went wrong in the module channel, because if it broke for you it has
broken for someone else.

**"I already uploaded and then fixed something."** Upload again. The latest
upload is the one that counts.

## Anything else to add

If you want to include extra work — a second notebook, some notes, a plot you
are pleased with — make a folder called `submission` inside the lab folder and
put it there. Everything in it goes into the zip.

## Deadlines and marks

Weekly labs are **pass/fail completion checkpoints**. No single one carries a
mark of its own. They feed the **lab portfolio, worth 25%**, which is assessed
on the trail across the semester rather than on any one week: your Week 1 data
dictionary is what Week 3 audits, and your Week 1 pipeline is what Week 2
trains on top of.

Deadlines are **23:59 on the Wednesday after each lab**. Late still counts as
submitted; it is simply recorded as late.

The Week 6 quiz, the Week 7 applied assignment and the Week 12 project are
submitted separately and carry their own marks.

## Keep your own copy too

The zip is the hand-in, not your archive. Commit your code, your data
dictionary and your datasheet to your own repository as well, and push. From
the setup note in Week 0:

> You need a repository with a real commit history from Week 1, because the
> final project is assessed partly on that history.

Building the zip does not commit anything for you.

## If you are stuck

In this order:

1. **Run `python setup_check.py`.** Most Week 1 problems are a missing package
   or a CSV in the wrong folder, and it names both.
2. **The troubleshooting section of the lab wrap-up.** It covers the five
   errors that actually come up in this lab.
3. **The module channel.** Post there rather than emailing — someone else has
   the same problem, and the answer helps everyone reading. Include the output
   of `python setup_check.py`, not "it doesn't work".
4. **Email.** Expect a reply within two working days.

Getting stuck on environment setup is normal and says nothing about your
ability. Getting stuck silently for three weeks is the version that causes real
damage.
