# Section 3: Explain it locally, LIME and where explanations mislead

## What You'll Learn

A global ranking cannot tell one refused applicant why. For that you need a local explanation. You'll fit LIME around a single decision, then spend the harder half of the section learning to distrust what it tells you.

## Exercise 3.1: LIME on one missed defaulter

Pick a specific person: a client who actually defaulted but whom the model waved through. LIME perturbs that client's features, watches how the model responds nearby, and fits a simple linear story to that neighbourhood.

**Step 1:** Explain one false negative:

```python
# section3_lime.py
import lime, lime.lime_tabular

lime_expl = lime.lime_tabular.LimeTabularExplainer(
    Xtr_t, feature_names=names, class_names=["no default", "default"],
    discretize_continuous=False, random_state=0)

fn_idx = np.where((yc_te.values == 1) & (pred == 0))[0]   # actually defaulted, model said no
i = int(fn_idx[0])
exp = lime_expl.explain_instance(Xte_t[i], clf.predict_proba,
                                 num_features=5, num_samples=5000)
print(f"client (test row {i}): model said default prob = {pp[i]:.3f}, and they DID default")
for feat, w in exp.as_list():
    print(f"   {feat:12s} {w:+.3f}")
```

The model gave this client a default probability of about **0.17** and approved them; they defaulted. LIME reads the decision as `PAY_1` pushing towards default (about **+0.10**) but `BILL_AMT1` and `PAY_AMT1` pulling the other way, and `SEX_2` nudging towards approval. A tidy, plausible, per-person story, and worth exactly as much scrutiny as it took to produce.

## Exercise 3.2: Now doubt the explanation

An explanation you have not attacked is one you are not allowed to quote. Attack this one two ways.

**Step 1:** Test stability. Re-run LIME with a different random seed and see whether the story survives:

```python
# section3_stability.py
lime_expl2 = lime.lime_tabular.LimeTabularExplainer(
    Xtr_t, feature_names=names, class_names=["no default", "default"],
    discretize_continuous=False, random_state=7)
exp2 = lime_expl2.explain_instance(Xte_t[i], clf.predict_proba,
                                   num_features=5, num_samples=5000)
top_a = [f for f, _ in exp.as_list()[:3]]
top_b = [f for f, _ in exp2.as_list()[:3]]
print("seed 0 top-3:", top_a)
print("seed 7 top-3:", top_b)
print("same three?  ", set(top_a) == set(top_b))
```

Here the top three come back identical. That is honest, and it is because the model is linear: a local linear surrogate of a linear model is stable. Do not over-learn the reassurance. Change the seed and you have tested only one of LIME's choices; the neighbourhood width is another, and on a tree ensemble or a network the neighbourhood you choose starts to change the story. Exercise 7.2 has you push on those other choices with this same model rather than assume they are harmless.

**Step 2:** Test the proxy worry. `SEX` shows up in the explanation, so ask the Week 5 question early: if you dropped `SEX`, could the model simply rebuild it from the other features?

```python
# section3_proxy.py
from sklearn.linear_model import LogisticRegression
ns_num = (["LIMIT_BAL", "AGE"] + [f"PAY_{i}" for i in range(1, 7)]
          + [f"BILL_AMT{i}" for i in range(1, 7)] + [f"PAY_AMT{i}" for i in range(1, 7)])
ns_cat = ["EDUCATION", "MARRIAGE"]
Xs, ys = df[ns_num + ns_cat], (df["SEX"] == 2).astype(int)   # predict "is female"
Xs_tr, Xs_te, ys_tr, ys_te = train_test_split(
    Xs, ys, test_size=0.25, random_state=0, stratify=ys)
sex_model = Pipeline([("prep", build_prep(ns_num, ns_cat)),
                      ("clf", LogisticRegression(max_iter=2000))]).fit(Xs_tr, ys_tr)
print(f"recover SEX from the other features: acc = {sex_model.score(Xs_te, ys_te):.3f} "
      f"(base rate = {ys.mean():.3f})")
```

You get about **0.612**, against a base rate of **0.604**. On this dataset `SEX` is barely recoverable: dropping it really would remove most of that signal. That is a genuinely useful and slightly surprising result, and the opposite of the lecture's synthetic credit model, where income was built from the protected group and leaked heavily. The lesson is not "proxies are always hiding"; it is "you have to *measure* recoverability rather than assume it either way".

The explanation is faithful (it correctly shows the model uses `SEX`), and the harm here is not a hidden proxy but the plain, visible use of a protected attribute.
