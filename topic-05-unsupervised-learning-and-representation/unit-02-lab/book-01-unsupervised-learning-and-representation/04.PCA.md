# Section 4: PCA, a representation you can watch being learned

## What You'll Learn

So far you have clustered in 27 dimensions, trusting distances you cannot see. PCA does two things at once: it compresses those 27 numbers into a handful, and, more importantly for this module, it *learns a new set of axes from the data itself*. This is your first formal encounter with a representation you can watch being built.

## Exercise 4.1: How much of the story lives in a few directions?

**Step 1:** Fit PCA and read the variance each component explains.

```python
# section4_pca.py
from sklearn.decomposition import PCA

pca = PCA().fit(Xt)
evr = pca.explained_variance_ratio_
print("PC1..PC4:", np.round(evr[:4], 3))                       # [0.309 0.193 0.071 0.055]
print("first two components:", round(evr[:2].sum(), 3))        # ~0.502
print("components for >= 90%:", int(np.argmax(np.cumsum(evr) >= 0.90)) + 1)  # 12
```

`PC1` carries about `31%` of the variance and `PC2` about `19%`, so the first two axes together hold only about half of everything, and you need twelve components to reach ninety per cent. This is the honest state of real data: it does not compress as neatly as the textbook two-dimensional picture. Reducing to two dimensions here is a genuine trade, you are throwing away half the variance to buy a plot you can look at, and whether that trade is worth it depends on what you do next.

**Step 2 (optional plot):** The scree plot makes the trade visible.

```python
# section4_scree.py
import matplotlib.pyplot as plt
xs = np.arange(1, len(evr) + 1)
plt.figure(figsize=(7, 4))
plt.bar(xs, evr, label="per component")
plt.plot(xs, np.cumsum(evr), "-o", color="crimson", label="cumulative")
plt.axhline(0.9, ls="--", color="grey"); plt.xlabel("principal component")
plt.ylabel("share of variance"); plt.legend(); plt.tight_layout(); plt.show()
```

## Exercise 4.2: Project to 2D and read what the axes are made of

**Step 1:** Project to two dimensions. This is your learned representation, the thing you will plot and interrogate.

```python
# section4_project.py
Z = PCA(n_components=2, random_state=42).fit_transform(Xt)
print("2D representation:", Z.shape)                           # (30000, 2)
```

**Step 2:** A plot with axes called `PC1` and `PC2` is unfinished. Read the loadings, the weights that combine the original features into each component, and name the axis in the language of the domain.

```python
# section4_loadings.py
load1 = pca.components_[0]
top = np.argsort(np.abs(load1))[::-1][:6]
print("PC1 is built mostly from:")
for i in top:
    print(f"  {feat_names[i]:12s} {load1[i]:+.3f}")
```

`PC1` is dominated by the six `BILL_AMT` features, all loading positively at around `+0.35`. That is not "PC1"; it is a **bill-size axis**, a measure of how large a balance the client carries. (Look at `PC2` the same way with `pca.components_[1]` and you will find it is driven by the `PAY_` repayment-delay features against `LIMIT_BAL`: a delinquency-versus-limit axis.)

**Reflection:** Naming `PC1` as "overall balance carried" rather than leaving it as "PC1" is the whole interpretive skill this week. It also explains Section 2's result: the biggest axis of variation in these clients is *how large their bills are*, which is exactly the big-balance minority K-means split off. The representation and the clustering agree on the main story, and it is a story about balance size, not about default.
