# Exercise 8 · Choosing

**8a · match.** A reference match (Table I):

| Situation | Method |
|---|---|
| (a) New, realistic examples of data you have plenty of | [2] a diffusion model, and check for copies |
| (b) You know roughly how a system moves, and have a short recording | [5] learn the rule of motion, keeping what you know |
| (c) The answer must not change when the input is turned or reordered, exactly | [6] build the symmetry in |
| (d) The answer barely changes with small shifts and blur, but not exactly | [4] augmentation (Week 9) |
| (e) A standard equation on a simple shape, and an answer you can trust | [3] a classical solver |
| (f) No reliable rule, plenty of labelled data | [1] ordinary machine learning |
| (g) No measurements, but you trust the equation | [7] a physics-informed network: let the equation teach |

**8b · compare.** The most common differences, and why the reference chooses as it does:

- **(c) and (d) swapped.** Building a symmetry in is a promise that it is *exactly* true; for a rough symmetry, that promise
  is false and becomes a wall (Exercise 6d). Augmentation only *encourages* the model, so it suits rough symmetries.
- **(e) answered with a neural ODE or a physics-informed network.** For a standard equation on a simple shape, classical
  solvers are faster, more accurate, and come with guarantees. The learned methods earn their place when data, unknown
  numbers or awkward shapes are involved.
- **(a) answered with augmentation.** Augmentation changes existing examples; a diffusion model makes genuinely new ones,
  which is why it needs the copy check from Exercise 3.
- **(g) answered with "nothing can be done".** Exercise 7 showed a network taught by the equation alone reaching an error of
  0.0001. With a trusted equation, zero data is not a dead end; the simulator route (E5) works too.
